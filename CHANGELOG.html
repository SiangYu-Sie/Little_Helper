Bug Fix

Issue 1 — PPID 列表顯示帶有多餘的 / 前綴

問題描述： 設備端回傳的 S7F20 PPID 字串帶有前置斜線（如 /Default、/Trim_1）， 導致 UI 列表、ComboBox 顯示不直觀，且手動輸入時需要加 / 才能比對。

根本原因： ParsePpidList() 直接取 ASCII 字串，未做任何清理。

修正方式： 在解析時加入 .TrimStart('/')，去除所有 PPID 的前置斜線。

修改前修改後
var s = sub.GetString(); var s = sub.GetString().TrimStart('/');

Bug Fix

Issue 2 — Formatted Recipe Body Download payload 結構錯誤

問題描述： 按鈕 (2.2) Formatted Recipe Body Download 與 (4.2) Formatted Recipe Body Download 呼叫了 S7F23UnformattedProcessProgramSend()（Unformatted 格式）， 送出的 payload 為 L[ A(PPID), B(...) ]，與 SECS-II S7F23 Formatted 規格不符，導致設備端回覆 ACKC7 = NAK。

根本原因： 沒有對應的 Formatted S7F23 方法，開發時誤用 Unformatted 版本。

修正方式： 在 SecsMessageFactory 新增 S7F23FormattedProcessProgramSend()， payload 結構參照 TOOLID.xml 定義：

項目內容
新方法名稱 S7F23FormattedProcessProgramSend(string ppid)
Payload 結構 L[ A(PPID), A(MDLN), A(SOFTREV), L[ L[ U2(CCODE), L[ A(PPARM) ] ] ] ]
修改的按鈕 (2.2) Formatted Recipe Body Download（Main）
(4.2) Formatted Recipe Body Download（Sub）

Issue 3 — Delete Recipe 後按 6.2 / 7.2 PPID List Inquiry 列表不更新

問題描述： Delete Recipe 成功後，按下 (6.2) PPID List Inquiry 或 (7.2) PPID List Inquiry 並不會更新左側的 PPID 結果文字框及所有 ComboBox，刪除後的 PPID 仍顯示在下拉選單中。

根本原因： 兩個按鈕原本只呼叫 SendAsync("...", 7, 19)，僅送出訊息並記錄 log， 未解析 S7F20 回覆也未更新 UI 控制項。

修正方式： 將 (6.2) 與 (7.2) 的動作改為直接呼叫 QueryPpidListAsync()， 與 (1) PPID List Inquiry 相同的完整流程（送出 → 解析 → 更新 TextBox + ComboBox）。

按鈕修改前修改後
(6.2) PPID List Inquiry () => SendAsync("L2Recipe_S7F19_Main_Check", 7, 19) QueryPpidListAsync
(7.2) PPID List Inquiry () => SendAsync("L2Recipe_S7F19_Sub_Check", 7, 19) QueryPpidListAsync
